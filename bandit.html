Linux / Security Fundamentals

OverTheWire Bandit

I worked through OverTheWire’s Bandit wargame to Level 28. Each level gave me a small Linux or networking puzzle, and the notes below capture what I learned and where I had to change my approach.

Linux Bash SSH Networking

Level notes

I focused on the ideas behind each command: how the shell interprets a filename, how permissions affect access, and how data moves between processes. Challenge passwords are intentionally not included.

Level 0 → 1 Getting oriented in a remote shell

I used pwd and ls -al to understand where I was and what files were present, then read the supplied file. The first lesson was to inspect the environment before guessing.

Level 1 → 2 A filename that looks like an option

A file named - is easy for a command to mistake for a flag or standard input. I learned to refer to it as ./- so the path makes my intent explicit.

Level 2 → 3 Spaces in filenames

The shell splits unquoted text on spaces, so I had to quote the filename (or escape its spaces) to make it one path instead of several arguments.

Level 3 → 4 Hidden files

I used ls -al to reveal a hidden file, then used file to check its type before reading it. The challenge reinforced that a normal directory listing can hide useful entries.

Level 4 → 5 Identifying the readable file

With many similarly named files, I used file * to inspect them in one pass and pick out the human-readable text. The useful move was narrowing the candidates by file type.

Level 5 → 6 Searching by file properties

The target was buried in nested directories. I explored recursively, then used find with a size constraint and checked the candidate’s permissions and type. This was my first practice turning the clues into search filters.

Level 6 → 7 Expanding the search scope

My first search stayed too close to the current directory. I moved up the filesystem and combined size, owner, and group filters; redirecting permission errors with 2>/dev/null kept the useful result visible.

Level 7 → 8 Searching a large text file

I used grep to find the line containing a known marker in a large file. A precise search term was much faster than reading the file manually.

Level 8 → 9 Finding the unique line

I learned that uniq only groups adjacent duplicates, so the lines need to be sorted first: sort followed by uniq -u. The ordering of a pipeline mattered.

Level 9 → 10 Readable strings in binary-looking data

The file contained noisy, non-printable data. I filtered for printable characters and searched around the challenge’s marker rather than treating the entire file as ordinary text.

Level 10 → 11 Base64 decoding

I recognized that the text was encoded rather than encrypted, then decoded it with base64. This helped distinguish a reversible representation from a security mechanism.

Level 11 → 12 ROT13 and character translation

I used tr to map each letter to the character thirteen places away. Writing out the source and destination alphabets made the transformation easier to reason about.

Level 12 → 13 File signatures and repeated decompression

This was a more involved file-format puzzle. I moved a copy into a temporary directory, inspected bytes with a hex dump, identified formats from their signatures, and repeatedly unpacked or decompressed the result. The tricky part was checking the file again after every transformation.

Level 13 → 14 SSH key authentication

I learned to save a provided private key locally and use ssh -i to authenticate as the next account. This connected file handling with public-key login.

Level 14 → 15 Connecting to a local service

I tried to identify what kind of service was listening, then connected to the local host and sent the data it expected. The key insight was that the task involved a port and a protocol, not another file to search.

Level 15 → 16 TLS with OpenSSL

I used openssl s_client to establish a TLS connection to a host and port. I learned to use a protocol-aware client when a service expects an encrypted connection.

Level 16 → 17 Scanning ports and testing services

I scanned a small port range with nmap, then tested the candidate services with OpenSSL. The challenge took some trial and error: an open port alone was not enough; I had to find the service that returned the expected kind of data.

Level 17 → 18 Comparing two files

I used diff to compare the old and new files and identify the changed line. A comparison tool made a small difference easy to spot in otherwise similar data.

Level 18 → 19 Interactive versus non-interactive shells

An interactive login triggered shell startup behavior that immediately ended my session. I had to understand what the shell was doing automatically and request the needed command in a non-interactive way instead.

Level 19 → 20 Setuid programs

I inspected a setuid helper and learned that it runs with the file owner’s privileges. The important security lesson was how much access a program can expose if it accepts arbitrary commands.

Level 20 → 21 Coordinating a listener and client

I used Netcat to listen on a port while the provided program connected back. Starting the listener in the background with & let both sides run at once; figuring out the order and timing took some experimentation.

Level 21 → 22 Tracing a cron job

I inspected the cron configuration and the script it launched, then followed the script to the temporary output file. This taught me to trace scheduled work from its configuration to its effects.

Level 22 → 23 Following a script’s variable logic

The cron script built a filename from a username variable. I had to read the script carefully and run through its logic with the relevant account name to predict where it wrote the result.

Level 23 → 24 Permissions, temporary files, and cron

I worked through which permissions let a scheduled script run, enter a directory, and write an output file. The subtle part was that directory execute permission controls traversal; I also compared mkdir with mktemp and saw why broad permissions such as 777 should not be the default choice.

Level 24 → 25 Automating a PIN search

I generated the four-digit PIN candidates with a shell loop and piped them through one Netcat connection. My first script approach kept opening new connections; I learned to keep one connection open and stream all candidates through it.

Level 25 → 26 Using a pager and escaping a restricted shell

I remembered that more becomes interactive when the output does not fit on screen. Making the terminal small enough opened that mode, from which I could launch an editor and switch to a usable shell. The challenge depended on understanding when a familiar command changes behavior.

Level 26 → 27 Using a setuid helper deliberately

I inspected the helper’s permission bits, noticed the setuid bit, and used it to run a command with the next account’s privileges. This built on the earlier lesson about reading permission strings rather than treating them as decoration.
